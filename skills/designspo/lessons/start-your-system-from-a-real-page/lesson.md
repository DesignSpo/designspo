It can be tempting to design a complete system before building any pages, with every color shade, font size and spacing step decided up front. The risk however is that many of those tokens never get used, while the ones you actually need turn out to be missing.

A more practical approach is to build one real page first, often the homepage. Then pull the colors, sizes and spacing it uses into tokens. Each new page after that either reuses those tokens or shows you what’s missing, so the system grows from real needs. This may feel slower at the start, but it usually leads to a smaller system that you’ll actually use.
